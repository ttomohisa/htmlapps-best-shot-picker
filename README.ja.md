似た写真を見比べてお気に入りを選び、元ファイルのままZIPでまとめて保存するツールです。

## デモ

### [Best Shot Pickerを開く](https://ttomohisa.github.io/htmlapps-best-shot-picker/)

インストールやアカウント登録は不要です。公開ページから最初のHTMLを取得した後、写真はブラウザー内で処理され、アップロードされません。

[![写真一覧・2枚比較・選択した元画像の保存画面](assets/screenshot.png)](https://ttomohisa.github.io/htmlapps-best-shot-picker/)

## 主な機能

- **写真をまとめて読み込む:** JPEG・PNG・静止画WebPに対応。作業途中でも追加できます。
- **似た写真を整理する:** 重複と保守的な類似グループを確認し、分割・結合・移動・取消ができます。
- **細部を見比べる:** 大きなプレビュー、2枚比較、100%・200%・400%表示、任意の顔位置拡大を使えます。
- **残す写真は自分で選ぶ:** 何枚でも選択でき、直前の変更は元に戻せます。未確認グループへ順に移動でき、技術的なヒントや任意のモデル候補が自動で写真を選ぶことはありません。
- **元のまま保存する:** 1つのZIPまたは独立した小分けZIPで保存。出力名の編集、同名ファイルの衝突回避、任意のJSON／CSV一覧に対応します。
- **単一HTMLで端末内処理:** 日英UI、キーボード操作、スマートフォン向けタブを備え、コードとモデルを内包してオフラインでも使えます。

## すぐに使う

### Webで使う

現行のChromeまたはEdgeで[アプリを開く](https://ttomohisa.github.io/htmlapps-best-shot-picker/)だけで利用できます。

### ダウンロードして使う

1. [best-shot-picker.html](https://github.com/ttomohisa/htmlapps-best-shot-picker/blob/main/best-shot-picker.html)をGitHubの「Download raw file」ボタンで保存します。
2. 保存したHTMLをブラウザーで開き、「写真を追加」を選びます。

### オフラインで使う

保存した `best-shot-picker.html` は、ネットワークを切った状態でも単体で使えます。`dist/index.html` も同じ通常版です。利用するだけならインストール、ローカルサーバー、Node.js、ビルドは不要です。

別形式の `dist/index.self-extract.html` はgzipから同じアプリを復元しますが、起動自体に `DecompressionStream` が必要です。開けない場合は通常版HTMLを使ってください。自分でビルドする手順は末尾の「開発・ビルド」をご覧ください。

## 使い方

1. **写真を追加する。** ファイル選択、ドラッグ＆ドロップ、対応環境ではフォルダー選択で読み込みます。追加しても「残す」の選択と手動グループは保たれます。読めないファイルは別に表示され、処理の中止や未完了分の再試行ができます。
2. **一覧から比較する。** グループまたは「すべての写真」を開き、「比較」でAとBを選びます。スマートフォンではA／Bを切り替え、100%・200%・400%では画像内をスクロールして確認します。代表サムネイルや技術候補は「残す」の選択ではありません。「グループ整理」で分類を調整できます。
3. **お気に入りを残す。** 何枚でも選べ、1組から0枚でも構いません。「次の未確認グループへ」は移動だけ、「確認済みにして次へ」は現在の組を確認済みにします。「元に戻す」で元の組へ戻せます。読み込み・解析中はこの操作を一時停止します。
4. **保存する。** 選択した写真とZIP名を確認し、「元画像をZIPで保存」を押します。ブラウザーのダウンロード状況と保存したZIPの中身を確認してから、ページを閉じてください。

### 任意の比較補助

「似た写真の候補を探す」は、解析済みの自動・未確認グループを2組以上、合計36枚以内で検索します。大量の写真がある場合は、この範囲でグループを選びます。1組で36枚を超えるものは検索できません。候補を確認してから「この組み合わせを適用」を押し、直前のグループ編集は取り消せます。手動・確認済み・対象外のグループは保護されます。写真やグループの変更、再解析、候補の適用で未適用候補は消えます。中止・失敗でも既存の組、選択、原本は変わりません。

「顔を探す」は比較中の写真ごとに最大6候補を表示します。それぞれ顔を選んで拡大し、「全体表示」で戻れます。誤検出や見逃しがある場合は通常の拡大を使ってください。

キーボードでは矢印キーで操作中の比較写真を切り替えます。はみ出した画像へTabで移動すると、矢印は画像内のスクロールに使えます。ページにフォーカスがあるときはEnterで「残す」を切り替え、操作部品にフォーカスがあるときはその通常操作を行います。Escでダイアログを閉じます。入力欄・選択欄では写真切替のショートカットは動きません。

### 小分けZIPと保存対象一覧

- 任意の小分けモードで32・64・128・256・512 MiBから容量を選びます。初期選択はなく、実機で安全と確認された既定容量もありません。
- サイズと個数を確認すると、開始時点の選択・格納名・出力名を計画に固定します。その後の編集は現在の写真一覧と次回の出力に反映され、進行中の計画には反映されません。
- 現在のZIPを作成してダウンロードし、ブラウザーの保存状況を確認してから「保存を確認して次のZIPへ」または「保存を確認して終了」を押します。自動ダウンロードや自動進行はありません。各ZIPは単独で展開でき、原本を分断しません。
- 中止・失敗時の再試行は現在のZIPだけです。再ダウンロード時は重複コピーを案内します。準備済み・要求済みの計画を破棄するときは、保存リンクの解放が未完了のダウンロードに影響し得るため確認します。
- 「保存対象の一覧を保存」はJSON／CSVを別ファイルに保存し、ZIPには入れません。残す写真の名前・保存先ZIP・順序・サイズだけを記録し、EXIF／GPSやモデル結果は含めません。通常ZIPでは現在の選択、小分けでは固定計画を使います。保存予定の一覧であり、保存完了の証明や作業のバックアップではありません。正確な名前はJSON、表示用はCSVです。[出力形式とCSVの制限](docs/SELECTION_LIST.md)もご確認ください。

## ブラウザーと検証状況

現行Chrome・EdgeのPC／スマートフォン向けに設計し、日英とも320px以上の幅を対象としています。フォルダー選択はブラウザーの対応状況によります。

**Android Chrome**では、端末に保存した写真から通常ZIPと独立した小分けZIPの両方を保存し、展開後の写真を開けたことを利用者が確認しています。この操作範囲の確認であり、安全な最大容量やすべてのAndroid端末での動作保証ではありません。

Windows・iPhoneの実機操作、Android／iPhoneの100・500枚、PCの1,000枚、ピークメモリ、実写真の処理性能は未検証または延期です。デスクトップエンジンや合成画像による自動確認とは区別し、[検証記録](docs/VALIDATION.md)に残しています。

任意の類似候補検索と顔検出はWeb Workersと `DecompressionStream` が必要です。利用できない場合も通常版HTMLの手動比較・「残す」・ZIP保存は使えます。APIがあっても、すべての端末でモデルの起動や処理完了を保証するものではありません。

## プライバシー

写真はすべてブラウザー内で処理します。モデルはHTMLに同梱され、明示操作時だけ動きます。画像のアップロード、実行時API、外部フォント、アクセス解析、外部モデルの取得はありません。アプリのCSPは `connect-src 'none'` で実行時接続を制限しています。

ZIPは元のバイト列を保持するため、**EXIF・GPS位置情報・色プロファイルなども残ります**。共有前にご確認ください。一覧のファイル名にも個人情報が含まれる場合があります。端末の原本を上書き・移動・削除しません。

**写真・選択・保存計画は一時的です。** 再読み込み、ページを閉じる、「最初から」で消え、セッションを復元する機能はありません。言語設定だけを保存する場合があります。終了前に保存を済ませてください。

## 制限と困ったとき

**v1.0.0は、既存機能に範囲を絞ったリリースです。** 当初計画の全項目に合格したという意味ではありません。一般の写真での精度、実機の大量処理・メモリの受け入れは延期しています。現在の公開範囲は[APP_SPEC.md](APP_SPEC.md)、[DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)、[ACCEPTANCE_MATRIX.md](ACCEPTANCE_MATRIX.md)をご覧ください。

- **対応形式:** JPEG・PNG・静止画WebPのみです。HEIC／HEIF・AVIF・RAW・TIFF・アニメーション画像・動画は非対応です。1億画素または一辺32,768pxを超える画像は読み込みませんが、あらゆる不正ファイルや低メモリ環境での失敗を防ぐ保証ではありません。
- **分類とヒント:** 通常の分類は非ML、任意の端末内モデル検索は試験的です。似た写真の見逃しや、無関係な写真の分類が起こり得ます。技術的なヒントは縮小画像の計測値であり、好みや被写体の価値を判断せず、人の好みとの一致率も未測定です。顔検出は拡大の補助で、目の状態・顔の順位付け・人物対応は行いません。[分類](docs/GROUPING.md)と[比較ヒントの制限](docs/QUALITY.md)も参照してください。
- **厳密な重複確認:** Web Cryptoが必要で、ハッシュ計算は1ファイル64 MiBまでです。省略された場合も手動選択と保存はできます。
- **ZIP容量とメモリ:** 各ZIPは65,535件未満・付加情報込みで4 GiB未満です。1原本と付加情報だけで小分け容量を超える場合は事前に停止するため、より大きい容量、選択の変更、通常ZIPを選んでください。指定容量は1つのZIPの上限で、ブラウザー全体のメモリ上限ではありません。ZIP64、ディスクへのストリーミング、1つのZIPを分断する形式はありません。ダウンロード開始や利用者の保存確認は、ディスク書き込み完了の検証ではありません。

### ZIP保存中に元画像を読めない場合

`ZIP_READ_FAILED` は元画像を再読込できなかったことを示します。サムネイルが見えても、あとから原本を読めるとは限りません。クラウド上の写真は端末へダウンロードし、**別タブ**で端末内ファイルを選び直してください。選択を保つため元のタブは閉じずに残します。選択は別タブへ自動で引き継がれず、復元もされません。

報告されたAndroidの事例では、クラウド提供元から選んだ原本のZIP読込時に `NotReadableError` が発生し、端末内ファイルでは成功しました。根本原因は未確定です。ZIP組立と保存リンクの準備は別の診断で表示し、それだけでメモリ不足とは断定しません。原因確認のための写真送信は不要です。

## 開発・ビルド

[AGENTS.md](AGENTS.md)、[APP_SPEC.md](APP_SPEC.md)、[構成ガイド](docs/ARCHITECTURE.md)を参照してください。編集対象は `src/` と設定で、生成HTMLを直接編集しません。固定モデルとハッシュ一覧は `assets/embedding/` と `assets/face-detection/` にあります。

Windowsでは `build-standalone.bat` を実行します。PowerShellの構文事前検査後、両HTML形式と通常版に一致するルートコピーを生成します。初回は固定依存パッケージをダウンロードする場合があります。リポジトリの確認には `scripts/check-repository.ps1` を実行してください。通常のWindowsビルドとアプリ利用にNode/npmは不要です。

既存のテスト環境にはNode.js 22以降を使います。

```sh
npm ci
npm test
npm run test:grouping
npx playwright install chromium
npm run test:browser
```

ブラウザーテストは自作の合成画像を使い、両HTML形式を `file://` で開きます。証拠の範囲は[検証記録](docs/VALIDATION.md)、分離した研究・診断は[画像埋め込みの技術検証](experiments/embedding/README.md)と[手動リソース診断](experiments/resource-probe/README.md)を参照してください。
